🎯 1. Visión y Objetivo
Desarrollar un sistema de Punto de Venta (POS) a la medida para la tiendita de abarrotes de los padres del usuario (75 y 72 años).
Digitalizar cobros (efectivo + tarjeta) sin alterar precios ni ganancias.
Dar control real de ventas y ganancias (día, semana, mes).
Reemplazar progresivamente la libreta + calculadora.
Monitoreo remoto desde la oficina (misma casa) vía LAN/Tailscale.
Herramienta adaptada a SUS capacidades, no al revés.
Soportar múltiples cajas desde el día 1.

👤 2. Perfil del Usuario Final (Padres)
Edad: 75 y 72 años.
Tecnología: Baja. Se frustran con interfaces complejas o textos pequeños.
Flujo actual REAL: Usan calculadora, libreta para anotar ventas del día. No hay control formal de inventario. Actualizan precios cada ~8 días.
Necesidad clave: Simplicidad extrema, certeza de que el botón funcionó, beneficio tangible visible.

🛡️ 4. Principios de Diseño (No Negociables)
Offline-first: El dispositivo debe seguir operando y sincronizar después si cae la red local.
Datos FUERA del dispositivo: Fuente de verdad en el servidor local.
Imágenes en el servidor: Se reutilizan, respaldan y cachean en el dispositivo cliente.
Target hardware: Responsive-first. Principal: Tablet Samsung Galaxy Tab A11+ (11", landscape). Adaptable a monitores de escritorio (futuras cajas) y laptops (auditoría remota).
Regla de los 3 toques: Máximo 3 interacciones táctiles para cobrar.
Feedback multisensorial: Sonido, vibración y cambio visual inmediato.
Augmentar, no reemplazar: El sistema registra lo que ya hacen.
Un precio único: Idéntico para efectivo y tarjeta. Sin recargos.
Multi-caja nativo: Soporta 2+ cajas sin cambios estructurales.

🏗️ 6. Arquitectura Técnica
✅ CERRADO — Backend
Lenguaje: Go 1.23+
Router: `net/http` estándar con path params nativos (Go 1.22+). Sin frameworks.
Dependencias: Mínimas (driver PostgreSQL y lo estrictamente necesario).
Justificación: Binario único, bajo consumo de RAM, concurrencia nativa.

✅ CERRADO — Topología / Servidor
Servidor: Laptop / Mini PC con Linux en otra habitación.
Red: 100% Red Local (LAN). No se requiere internet para operar.
Energía: Servidor y router conectados a No-break (UPS).
Dispositivo cliente: Tablet Samsung Galaxy Tab A11+ (11", 6GB RAM, 128GB). Datos e imágenes residen en el servidor.
Acceso remoto: Tailscale (VPN privada) para auditoría remota.

✅ CERRADO — Base de Datos
Motor: PostgreSQL (robustez, concurrencia y escalabilidad).
Backups: `pg_dump` automatizado + retención local/nube.

✅ CERRADO — Almacenamiento de Imágenes
Ubicación: Carpeta `/images/products/` en el servidor local.
Flujo: API de Go sirve las imágenes. El dispositivo cliente las descarga y cachea.

✅ CERRADO — Flujo de Sincronización y Multi-Caja
Normal (99%): Cliente → Venta → Servidor (PostgreSQL) → ✅ Guardado.
Offline (1%): Cliente → Venta → IndexedDB (local) → ⏳ Pendiente. Sincronización automática al recuperar red.
Multi-caja: Soportado nativamente con `terminal_id` en tabla `sales`.

✅ CERRADO — Frontend
Stack: React 18+ + Vite + TypeScript + Tailwind CSS + Dexie.js + PWA (`vite-plugin-pwa`).
Gestor de paquetes: `pnpm`.
Enfoque: Responsive-first (breakpoints de Tailwind: `sm`, `md`, `lg`, `xl`, `2xl`).
Justificación: SPA ligera, offline-first, type safety para cálculos de dinero, control total sobre UX para adultos mayores.

✅ CERRADO — Hardware Cliente
Modelo: Samsung Galaxy Tab A11+ (11", 6GB RAM, 128GB, Android 16).
Justificación: Pantalla amplia para botones ≥60px, RAM suficiente para caché de imágenes, batería de 15h.

💰 7. Regla de Negocio: Precios, Comisiones e Inventario ✅ CERRADO

Estrategia de precios: Margen integrado al precio base. NO hay recargo en el momento de la venta.
Precio único: Idéntico para efectivo y tarjeta, redondeado a `.50` o entero.
Cálculo silencioso: El backend calcula la comisión por cada pago y la registra como gasto operativo.

🏦 Terminal Física (Agnóstica)
Proveedor Beta: Mercado Pago Point.
Tasa configurable: 4.1% (0.041) — incluye IVA (3.5% + 16% = 4.06%, redondeado por seguridad).
Se aplica sobre el `sale_price`.

💳 Pagos Mixtos (Backend blindado, UI simple en Beta)
Beta: UI solo permite UN método de pago por venta.
Backend: Tabla `sale_payments` soporta N pagos. Futuro: habilitar UI sin refactor.

📦 Inventario (Decremento silencioso + Auditoría)
Beta: `stock_quantity` se decrementa al vender. Registro en `inventory_movements`.
Dispositivo cliente NO bloquea ventas por stock bajo. Panel de admin muestra alerta si `stock_quantity < low_stock_threshold`.
Futuro: UI para movimientos manuales (`PURCHASE`, `ADJUSTMENT`, `DAMAGE`).

💡 Cálculo de Costo y Sugeridor de Precio
Costo Real: El `cost_price` registrado será siempre el costo total real por unidad (incluyendo IVA/IEPS pagados en el ticket de compra), garantizando que la "ganancia neta" sea dinero real en efectivo.
Sugeridor Automático: Al registrar/actualizar, el sistema sugiere: `Precio = (Costo * 1.20) / 0.959`, redondeado hacia arriba a .50 o entero. Muestra simulador de ganancia neta (efectivo vs tarjeta) en tiempo real antes de guardar.

Fórmulas:
`total_bruto` = Σ(precio_venta × cantidad)
`total_neto` = `total_bruto` - Σ(terminal_commission de cada pago)
`ganancia_neta` = `total_neto` - Σ(costo_producto × cantidad)

🗄️ 8. Modelo de Datos (PostgreSQL)
-- 8.1 products (con soporte de inventario)
CREATE TABLE products (
id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
name TEXT NOT NULL,
cost_price DECIMAL(10,2) NOT NULL,
sale_price DECIMAL(10,2) NOT NULL,
stock_quantity INTEGER DEFAULT 0,
low_stock_threshold INTEGER DEFAULT 5,
image_url TEXT,
is_active BOOLEAN DEFAULT TRUE,
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 8.2 sales
CREATE TABLE sales (
id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
terminal_id TEXT NOT NULL,
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
total_bruto DECIMAL(10,2) NOT NULL,
total_neto DECIMAL(10,2) NOT NULL,
status TEXT DEFAULT 'COMPLETED' CHECK (status IN ('COMPLETED', 'SYNC_PENDING'))
);

-- 8.3 sale_items
CREATE TABLE sale_items (
id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
sale_id UUID NOT NULL REFERENCES sales(id) ON DELETE CASCADE,
product_id UUID NOT NULL REFERENCES products(id),
quantity INTEGER NOT NULL,
unit_price_at_sale DECIMAL(10,2) NOT NULL
);

-- 8.4 sale_payments (permite múltiples pagos por venta)
CREATE TABLE sale_payments (
id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
sale_id UUID NOT NULL REFERENCES sales(id) ON DELETE CASCADE,
payment_method TEXT NOT NULL CHECK (payment_method IN ('EFECTIVO', 'TARJETA')),
amount DECIMAL(10,2) NOT NULL,
terminal_commission DECIMAL(10,2) DEFAULT 0.0,
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 8.5 daily_cuts
CREATE TABLE daily_cuts (
id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
cut_date DATE NOT NULL UNIQUE,
total_cash_expected DECIMAL(10,2) DEFAULT 0.0,
total_card_neto DECIMAL(10,2) DEFAULT 0.0,
actual_cash DECIMAL(10,2),
difference DECIMAL(10,2),
notes TEXT,
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 8.6 settings (configuración dinámica)
CREATE TABLE settings (
key TEXT PRIMARY KEY,
value TEXT NOT NULL,
description TEXT
);
-- Registro inicial: ('card_commission_rate', '0.041', 'Comisión terminal bancaria en decimal (incluye IVA)')

-- 8.7 inventory_movements (auditoría completa de inventario)
CREATE TABLE inventory_movements (
id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
product_id UUID NOT NULL REFERENCES products(id),
movement_type TEXT NOT NULL CHECK (movement_type IN ('INITIAL_STOCK', 'SALE', 'PURCHASE', 'ADJUSTMENT', 'DAMAGE')),
quantity INTEGER NOT NULL,
reference_id UUID,
notes TEXT,
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
